## One plate, many impressions

In intaglio printmaking, an image is cut into a copper plate, and every print pulled from the plate is
the same. Here the plate is a `Scene`: an immutable tree of graphical primitives that contains no
renderer types. Every backend draws that one scene, and all of them run the same conformance tests.

<CardGrid>
	<Card title="SVG" icon="document">
		Markup as a `String`, byte-identical on the JVM and Scala.js with the default text metrics. A mark can carry its own title,
		description, CSS class, and `data-*` attributes.
	</Card>
	<Card title="PNG and Java2D" icon="seti:image">
		A `BufferedImage` or PNG bytes on the JVM, or drawing into a `Graphics2D` that you own.
	</Card>
	<Card title="PDF" icon="open-book">
		A vector page through Apache PDFBox, with the fonts you supply embedded and subset.
	</Card>
	<Card title="Canvas" icon="laptop">
		Draws into a browser `CanvasRenderingContext2D` under Scala.js.
	</Card>
	<Card title="JavaFX" icon="seti:java">
		Draws into a JavaFX canvas. OpenJFX is a `Provided` dependency, so your application supplies it.
	</Card>
	<Card title="Notebooks" icon="puzzle">
		Jupyter MIME bundles built on the SVG renderer, with a plain-text fallback.
	</Card>
</CardGrid>

Each backend is a separate artifact, so a portable library that depends on `intaglio-core` never
pulls in a desktop toolkit or a PDF library. [Backends](guides/backends/) compares what each one
can and cannot express.

## What the compiler and the types catch

<div class="intaglio-three">
<CardGrid>
	<Card title="Missing positions are compile errors">
		`geomPoint()` cannot be called until both `x` and `y` are mapped. The builder's type records which
		positions are mapped.
	</Card>
	<Card title="Failures are values">
		Building, compiling, and rendering return `Either`. Every error type extends `IntaglioError`, so one
		`flatMap` chain carries the compiler's and the renderer's failures together.
	</Card>
	<Card title="Dropped rows are reported">
		A row that cannot be drawn, such as one with a `NaN` position, appears in `droppedRows` with a typed
		reason. It is never discarded silently.
	</Card>
</CardGrid>
</div>

## Status

<Aside type="caution" title="Pre-release development software">
	APIs, semantics, and package boundaries may change. No stable support or binary-compatibility
	promise should be inferred. Intaglio is not yet published to Maven Central; build it from source.
</Aside>

Intaglio is 0.1 development software with no published release. It is built and tested with Scala
3.3.8 (the LTS) and 3.9.0, on JDK 17, 21, and 25, for the JVM and Scala.js. The JavaFX tests need
JDK 21 or later. To use it now, publish the artifacts to your local repository:

```sh
git clone https://github.com/canardlapin/intaglio.git
cd intaglio
sbt publishLocal
```

sbt prints the version it published, which is derived from the Git commit. Depend on the core and
one backend with that version. `%%%` resolves the JVM or Scala.js artifact and needs the Scala.js
sbt plugin; a JVM-only build can use `%%`.

```scala
libraryDependencies ++= Seq(
  "io.github.canardlapin" %%% "intaglio-core" % "<version>",
  "io.github.canardlapin" %%% "intaglio-svg" % "<version>"
)
```

Before 1.0, a `0.y.0` release may break the public API and a `0.y.z` release may not. The
[compatibility policy](contracts/compatibility/) defines what counts as breaking.
